# Lumiere MVP 原型设计规格

- 状态：原型设计基线
- 适用里程碑：Milestone 1 — HDR-aware MVP
- 适用平台：Windows、macOS
- 读者：产品设计、UI/UX 设计、产品与工程评审者
- 上位约束：[产品合同](../contracts/product.md)、[UI 合同](../contracts/ui.md)、[宣称与输出合同](../contracts/claims.md)

## 1. 文档目的

本文档把 Lumiere 的 MVP 产品合同转化为可执行的原型设计输入，定义原型必须覆盖的功能、页面、用户流程、系统状态、反馈语义和验收清单。

本文档不替代上位合同，不定义底层捕获实现，也不记录开发进度。发生冲突时，以产品、UI、宣称与输出合同为准；实际进度以 GitHub Issue 和 [`CURRENT.md`](../state/CURRENT.md) 为准。

## 2. 产品定义

Lumiere MVP 是一款面向 Windows 和 macOS 的轻量截图工具。用户可以从主窗口、托盘或菜单栏、全局快捷键发起区域截图或显示器截图。应用通过平台原生 HDR-aware 捕获管线获取画面，统一生成 **sRGB Visual Match** 结果，并将结果复制到剪贴板、保存到本地文件夹，或同时执行两者。

MVP 可以识别并诚实呈现当前目标的 HDR 能力，但不承诺导出文件保留 HDR，也不提供 HDR、P3 或 tone mapping 参数供用户选择。

### 2.1 核心体验目标

1. **快**：高频截图入口直接，区域选择和完成反馈不拖延操作。
2. **准**：普通 SDR 内容保持稳定，HDR 高光平滑压缩，避免明显泛白、发灰、过曝、过暗或色偏。
3. **稳**：重复截图、取消和退出后不残留 Overlay 或捕获状态。
4. **诚实**：复制或保存成功只表示产物已交付，不暗示 HDR 保留或视觉保真已经得到认证。
5. **原生**：尊重 Windows 和 macOS 的窗口、菜单、权限、快捷键和焦点习惯。MVP 只提供深色主题，不跟随系统明暗切换。

## 3. 原型范围

### 3.1 必须纳入

- 主窗口截图入口
- Windows 托盘与 macOS 菜单栏入口
- 用户配置的全局快捷键入口
- 区域截图
- 当前活动目标的显示器截图
- 剪贴板、文件夹、两者同时输出
- 输出目录、时间戳或文件命名、快捷键、捕获后行为和 HDR 提醒设置
- sRGB Visual Match 输出说明
- 目标相关的 HDR 能力状态
- 系统权限流程
- Native Host 不可用和捕获失败流程
- 成功、部分成功和失败反馈
- 键盘、焦点、缩放和降低动态效果状态

### 3.2 不纳入 MVP

- HDR-preserved 文件导出
- HDR10、JXR 或 P3 输出模式
- 用户可调的 tone mapping 或色彩参数
- 图片编辑、标注、马赛克、画笔、箭头或文字
- 截图历史、图库和素材管理
- 云端上传、分享链接、账户和登录
- 浅色主题与跟随系统明暗切换
- Onboarding 和遥测
- 对所有显示器、查看器、DPI、Retina 或混合拓扑的普遍一致性承诺
- 通用 HDR 保真、HDR 认证或“所有输出均保留 HDR”等产品宣称

### 3.3 可探索但未承诺

以下能力可以在原型中作为对比方案探索，但在产品决策确认前不得作为 MVP 必交付功能：

- 截图结果预览
- 选区完成后的移动和二次缩放
- 八方向选区手柄
- 指针像素放大镜
- 独立的显示器截图快捷键
- 开机启动
- 声音反馈
- 系统通知与应用内 Toast 的具体组合

## 4. 用户与使用情境

### 4.1 主要用户

- 日常需要快速截图的 Windows 和 macOS 用户
- 关注 HDR 画面可信度的设计师、工程师、作者和评审者
- 使用 HDR 或混合显示器环境，需要明确能力边界的高级用户

### 4.2 高频任务

1. 使用快捷键框选区域并复制到剪贴板。
2. 框选区域并保存到固定文件夹。
3. 截取当前显示器，同时复制和保存。
4. 修改默认输出目标或保存目录。
5. 第一次在 macOS 上截图时完成屏幕录制授权。
6. 在 HDR 能力不可用、降级或未经验证时理解当前状态并决定是否继续。

## 5. 信息架构

MVP 采用紧凑的桌面工具结构，不设计成 Dashboard。

```text
Lumiere
├── 主窗口
│   ├── 区域截图
│   ├── 显示器截图
│   ├── 当前输出目标
│   ├── 捕获与 HDR 状态
│   └── 设置入口
├── 区域截图 Overlay
├── 托盘 / 菜单栏菜单
├── 设置
│   ├── 输出
│   ├── 捕获
│   └── 系统与关于
├── 权限与能力状态
└── 捕获结果反馈
```

## 7. 页面与表面规格

### 7.1 主窗口

#### 目的

让用户快速发起截图、确认当前输出去向，并看见影响捕获的关键状态。

#### 必备内容

- 区域截图主操作
- 显示器截图次操作
- 当前输出目标摘要
- HDR-aware 捕获状态摘要
- 权限或 Native Host 异常提示
- 设置入口

#### 状态

- 正在检测捕获能力
- 捕获可用
- 权限未授予
- Native Host 不可用
- 捕获进行中
- 最近一次操作完成或失败

#### 设计约束

- 保持紧凑、稳定的窗口尺寸和清晰的操作层级。
- 正常状态下不展示底层像素格式、API 名称或内部验证术语。
- 捕获能力不可用时不得提供看似可点击但必然失败的主操作。
- 不加入宣传 Hero、统计卡片、历史列表或装饰性仪表盘。

### 7.2 区域截图 Overlay

#### 目的

让用户以最少步骤选择屏幕区域，并在释放鼠标时完成截图。

#### 必备元素

- 背景遮罩
- 稳定的选区边框
- 选区尺寸信息
- 简短的取消提示
- 捕获中的非阻断反馈

#### 状态

1. 等待选择
2. 正在拖拽
3. 已形成有效选区
4. 无效或过小选区
5. 正在捕获
6. 已取消
7. 捕获失败
8. Overlay 意外失焦或显示器拓扑变化

#### 设计约束

- 指针移动时，选区几何和控件不得跳动。
- 取消后立即退出 Overlay，不保留陈旧选区。
- 动效应短促、反映状态且不延迟截图。
- Overlay 是自定义 UI，但不能通过视觉表现暗示 HDR 保真已经得到认证。

### 7.3 托盘与菜单栏

#### 菜单结构

```text
区域截图          [快捷键]
显示器截图        [快捷键，如已配置]
------------------------------
打开 Lumiere
设置…
------------------------------
退出 Lumiere
```

Windows 使用系统托盘语义，macOS 使用菜单栏语义；文案、间距、焦点和分隔方式遵循平台惯例。

Lumiere 默认静默驻留：macOS 作为不显示 Dock 和应用菜单的纯菜单栏应用，Windows 仅驻留系统托盘；
启动和关闭主窗口都不退出后台进程。只有 `Open Lumiere`、`Settings…`、Windows 托盘点击或用户点击
失败通知等明确操作才显示主窗口，菜单截图与全局快捷键保持后台执行。macOS 启动时只读检查 Screen
Recording 权限；权限未授予或存在未完成的权限恢复步骤时，每次启动都显示对应的阻断式权限表面，但
系统授权请求仍必须由用户在该表面显式触发。Host 暂时不可用、HDR 提醒和普通输出问题不触发启动显窗。

### 7.4 设置

设置是 Lumiere 主窗口内的一种模式，不创建第二个 `BrowserWindow`。Capture 与 Settings 使用相同且稳定的
窗口尺寸；从主界面的 Settings 入口进入设置。Windows 使用标题左侧的返回箭头返回 Capture（32 × 32 点击区域、16px 图标，辅助名称与提示为 `Back to capture`）；macOS 保留标题栏中的 Done。设置修改即时保存，返回操作不承担保存。Windows 设置顶栏与主界面使用相同背景、46px 内容高度及底部分隔线，右侧保留原生窗口控件区域。macOS 继续使用
`titleBarStyle: 'hiddenInset'`，Windows 继续使用 `titleBarStyle: 'hidden'` 配 `titleBarOverlay`，窗口拖拽区和
原生窗口控件行为保持平台一致。

设置分类使用与内容列等宽的 beUI Dock：Output、Capture、System & About 分别使用图像结果、取景框和信息图标，
三个入口等分可用宽度，活动项以滑动圆角块表示。标题栏与 Dock 之间保持清楚的区域间距，Dock 与首个设置项保持更紧密的内容间距。设置项通过
留白分组，不使用逐行分割线；未实现或不可用的设置必须显示真实状态，不得伪装成可操作控件。

不使用 macOS vibrancy 材质。截图工具的窗口经常出现在用户正在捕获的画面里，半透明会把背后内容带进
输出；材质透出的颜色也让深色对比度不可预测。托盘弹出面板可以例外。

#### 输出

- 默认输出目标：剪贴板 / 文件夹 / 两者
- 默认保存目录：由原生目录选择器修改；未选择自定义目录时使用系统图片目录下的 `Lumiere`
- 时间戳或文件命名策略
- 文件名示例

保存目录由主进程持久化，Renderer 只能发起一次目录选择任务，不能提交任意文件系统路径。文件交付仍由
Native Host 完成。目录不存在时 Host 可以创建；无法创建或写入时只将文件夹目标报告为失败，不得覆盖同一次
捕获中已经成功的剪贴板交付。现有平台 `Lumiere` 时间戳文件名和冲突后缀规则保持不变，本切片不提供编辑能力。

#### 捕获

- 区域截图快捷键
- 显示器截图快捷键，如产品确认纳入
- 捕获后行为：`Do nothing` 或 `Show in folder`，默认 `Do nothing`
- HDR 状态提醒：开启 / 关闭，默认开启

`Show in folder` 只在文件成功保存并返回真实文件路径时定位该文件。仅复制成功、文件保存失败、捕获失败或用户取消时不执行附加动作。定位失败不得把已经成功的文件交付改写为截图失败。结果反馈始终独立保留，不受捕获后行为设置影响。结果预览不进入 MVP。

HDR 状态提醒只承载当前目标的非阻断状态。开启时，`unvalidated` 以及 Host 仍声明捕获可用的
`unavailable` 在状态持续期间显示安静的提醒，并明确仍可生成 sRGB Visual Match 输出；`ready` 保持静默。
关闭后仅隐藏这些可选提醒，不改变真实 HDR 状态、捕获能力、权限、Native Host 或失败反馈。是否允许继续
截图始终由 Host 声明的捕获能力决定，不能仅由 HDR 状态推断。

#### 系统与关于

- 屏幕捕获权限状态
- Native Host 状态
- 应用版本
- 输出语义的简短说明

建议说明文案：

> Lumiere 使用原生 HDR-aware 捕获，并生成适合日常剪贴板和文件使用的 sRGB Visual Match 图像。

### 7.5 权限与能力表面

权限提示负责解释、引导和重新检测，不模拟系统授权界面。

必须覆盖：

- 首次请求权限
- 用户拒绝权限
- 引导前往系统设置
- 用户返回应用
- 正在重新检测
- 权限已授予
- 权限仍不可用

macOS 的替换升级可能使旧的 Screen Recording 授权不再匹配当前应用身份。Lumiere 只在“已识别为升级安装”且一次真实截图返回权限失败后，使用同一阻断式权限表面提供恢复；不在后台静默重置，也不把此流程带到 Windows：

1. `Screen recording access needs a reset`：主操作 `Reset and restart`，次操作 `Not now`。
2. 用户确认后，只执行 `/usr/bin/tccutil reset ScreenCapture io.github.sousouliao.lumiere`，成功后重启应用。
3. `Allow screen recording again`：主操作 `Allow screen recording` 通过 Native Host
   显式请求权限，另提供 `Open System Settings` 与 `Check again`；从系统设置返回应用时自动重新检测。
4. 运行中的进程检测到授权后显示 `Restart Lumiere to finish`，提供 `Restart now` 与
   `Check again`；无论使用系统退出重开还是应用按钮，新进程启动时检测到授权都直接回到普通就绪表面，不再请求第二次重启。
5. 重置失败时显示 `Permission reset didn’t finish`，提供复制上述精确 Terminal 命令与重试。不得重置其他应用或其他 TCC 服务。

`Not now` 返回常规权限恢复，不清除本版本的恢复资格；同一版本再次发生权限失败时可以重新显示升级恢复。一次真实截图成功后，结束本版本的升级恢复资格。首次安装继续使用普通首次授权流程。

### 7.6 捕获结果反馈

结果反馈应回答三个问题：

1. 发生了什么？
2. 产物去了哪里？
3. 如果失败，用户下一步可以做什么？

推荐语义：

| 情况 | 推荐反馈 |
|---|---|
| 仅复制成功 | 已复制到剪贴板 |
| 仅保存成功 | 已保存到“{文件夹名称}” |
| 两者都成功 | 已复制并保存到“{文件夹名称}” |
| 复制成功、保存失败 | 已复制到剪贴板，但未能保存文件 |
| 保存成功、复制失败 | 已保存文件，但未能复制到剪贴板 |
| 两者都失败 | 未能交付截图，请重试 |
| 用户取消 | 静默返回就绪状态 |

“已复制”或“已保存”只表示 artifact success，不表示视觉匹配或 HDR 保留已经通过验证。

#### 已确定的展示与恢复行为

- 主窗口、全局快捷键和托盘入口共用主进程的截图操作状态。开始准备截图即进入忙碌状态，直到结果返回；切换设置页面不会重置状态，重复触发不覆盖当前操作。
- 主窗口保持固定尺寸。非阻断提醒和截图失败先在底部状态栏显示摘要；用户点击摘要后，详情替换中央内容区，不叠加在截图按钮之上，也不引入内容区滚动。
- 成功截图保持静默，主窗口底部只更新结果文字；不弹 Toast、系统通知或自动打开主窗口。`Do nothing` 不执行附加动作；`Show in folder` 仍只在文件保存成功后定位该文件。
- 用户取消不弹提示，主窗口恢复就绪状态。
- 部分成功或失败时，前台主窗口在底部状态栏保留摘要，点击后进入中央详情页并显示恢复操作，不重复发通知。如果正在设置页面，则回到截图页面展示摘要。
- 主窗口不在前台时，部分成功或失败使用一条无声系统通知，明确发生的问题，点击后打开主窗口的截图页面。系统通知不可用或被用户关闭时，仍保留主窗口里的结果；不回退到自定义弹窗或强制激活窗口。
- 每次结果最多发一条通知；新截图开始、主窗口获得焦点或退出时清除旧通知。过期通知与恢复操作不能覆盖当前截图。
- 权限、Native Host 或其他阻断状态用恢复内容替换主截图操作区，保留输出摘要；状态解除后原位恢复截图操作。详情页通过返回操作或 `Escape` 回到截图页，并将键盘焦点还给底部摘要。
- 反馈保留已成功的交付事实。`Capture again` 表示重新截图，不承诺重投递已释放的原始帧。权限失败提供 macOS 系统设置入口和 `Check again`；保存目标失败提供目录选择；其他交付问题可打开输出设置或重新截图。
- 主进程在本次应用运行期间保留最近结果，重新打开主窗口可见；开始新截图时清除旧结果。此状态不形成持久化历史或图库。所有恢复操作只作用于当前结果。

## 8. 核心用户流程

### 8.1 区域截图到剪贴板

```text
快捷键 / 主窗口 / 托盘或菜单栏
→ 检查权限与捕获能力
→ 进入区域 Overlay
→ 拖拽选区
→ 释放鼠标
→ 原生捕获
→ 固定 sRGB Visual Match 转换
→ 写入剪贴板
→ 显示“已复制到剪贴板”
```

### 8.2 区域截图到文件夹

```text
发起区域截图
→ 完成选区
→ 捕获与转换
→ 生成文件名
→ 保存到默认目录
→ 显示文件名或保存位置
```

### 8.3 显示器截图并同时输出

```text
发起显示器截图
→ 确认当前活动目标
→ 检查目标相关 HDR 状态
→ 捕获与转换
→ 写入剪贴板 + 保存文件
→ 分别汇总两个输出结果
```

### 8.4 首次使用且缺少权限

```text
用户发起截图
→ 检测到权限缺失
→ 解释权限用途
→ 打开系统设置
→ 用户完成授权并返回
→ 重新检测
→ 权限可用后继续或重新发起截图
```

应用是否自动续接此前的截图动作属于待决策项。原型至少应展示“继续截图”和“权限已就绪，请重新截图”两种方案的取舍。

### 8.5 HDR 状态非 Ready

```text
识别当前目标
→ unavailable / degraded / unvalidated
→ 解释当前状态及影响
→ 根据实际捕获能力允许继续或阻止
```

HDR 能力不可用不一定等于整个截图功能不可用。必须区分“无法使用 HDR-aware 路径但仍能合法截图”和“Native Host 不可用，无法截图”。在平台能力合同明确前，原型应保留两种分支。

### 8.6 取消与恢复

```text
进入 Overlay
→ 用户按 Esc 或执行平台等价取消动作
→ 立即关闭 Overlay
→ 清除选区与捕获状态
→ 返回截图前状态
```

在 Overlay 尚未发出原生 `capture` 请求时，共享 Shell 拥有取消、选区清理和 Overlay 关闭；点击未拖拽或
未形成有效选区都按取消处理，不产生原生请求。有效选区释放后立即发出捕获，不提供移动、手柄或二次调整。
原生请求发出后，Native Host 拥有捕获任务、原生资源清理和最终 `cancelled` 结果；应用退出则销毁 Host
进程并清理 Shell 中的等待状态。MVP 不提供捕获已发出后的独立中断操作。

Region Overlay 使用 `getCapabilities` 返回的短期目标 token。选区以目标左上角为原点、使用目标内逻辑
坐标；显示器缩放、原生坐标系和像素对齐全部由 Native Host 转换。目标失效、拓扑变化或选区越界都按
`capture-unavailable` 恢复，不允许 Shell 猜测原生显示器标识。

## 9. 状态矩阵

### 9.1 捕获能力

| 状态 | 是否允许截图 | 界面行为 |
|---|---:|---|
| 正在检测 | 否 | 主操作暂时禁用，显示短暂检测状态 |
| 可用 | 是 | 正常提供截图操作 |
| 权限未授予 | 否 | 解释权限并提供系统设置入口 |
| Native Host 不可用 | 否 | 禁用捕获，提供重试或恢复建议 |
| 平台不支持 | 否 | 说明当前系统环境不受支持 |
| 目标刚刚变化 | 暂停 | 重新检测目标相关能力后恢复 |

### 9.2 HDR 状态

| 内部状态 | 建议用户文案 | 默认处理原则 |
|---|---|---|
| `ready` | HDR-aware 捕获已就绪 | 正常截图，不需要持续强调 |
| `unavailable` | 此目标无法使用 HDR-aware 捕获 | 根据实际捕获能力允许继续或阻止 |
| `degraded` | 可以截图，但当前显示环境可能影响视觉效果 | 非阻断提醒，允许继续 |
| `unvalidated` | 可以截图，但此显示环境尚未经过验证 | 非阻断提醒，允许继续 |

最终文案必须避免“已认证”“完全准确”“保留 HDR”等含义。

### 9.3 输出结果

| 剪贴板 | 文件 | 总体结果 | 反馈原则 |
|---|---|---|---|
| 成功 | 不适用 | 成功 | 告知已复制 |
| 不适用 | 成功 | 成功 | 告知文件位置 |
| 成功 | 成功 | 成功 | 合并反馈 |
| 成功 | 失败 | 部分成功 | 保留已成功事实，提供保存恢复建议 |
| 失败 | 成功 | 部分成功 | 保留已成功事实，提供复制重试建议 |
| 失败 | 失败 | 失败 | 说明未交付并提供重试 |

### 9.4 Overlay 异常

- 用户未形成有效选区
- 捕获目标在选择期间消失
- 显示器断开或拓扑变化
- Overlay 意外失焦
- 原生捕获超时或失败
- 用户在捕获过程中退出应用

所有异常路径都必须确保 Overlay 可以关闭，捕获状态可以清理，并允许下一次截图重新开始。

## 10. 交互与视觉原则

### 10.1 层级

- 区域截图作为最高频主操作。
- 显示器截图作为清晰可见的次操作。
- HDR 状态只在影响决策时提升视觉权重。
- 设置和技术说明不与截图主操作竞争。
- 文案只写控件本身说不出的事：消歧、后果、阻塞原因、失败后的下一步。重复标签、平台常识和设计注释不进产品界面。

### 10.2 色彩与材质

- 强调色只作为点缀出现：图标、1px 描边、选区边、焦点环和状态点，不用于大面积填充。
- 操作层级靠表面明度和图标区分，主操作不依赖强调色色块。
- 材质和阴影只用于表达真实层级，如 Overlay 上方的尺寸标签。
- 避免紫蓝渐变、发光边缘、低对比度文字和装饰性大卡片。

### 10.3 动效

- 动效短促、可中断，不延迟捕获或完成反馈。
- reduced motion 下移除非必要位移和缩放。
- 捕获中的反馈应表达状态，不制造不确定的长时间等待动画。

### 10.4 键盘与焦点

- 所有主窗口和设置控件可通过键盘访问。
- 焦点必须可见。
- `Esc` 优先用于取消当前截图或关闭临时表面。
- 快捷键冲突必须在保存前或保存时明确提示。

## 11. 文案规则

### 11.1 应使用

- HDR-aware 捕获
- sRGB Visual Match
- 已复制到剪贴板
- 已保存到“{文件夹名称}”
- 可以截图，但此显示环境尚未经过验证
- 当前无法截图，请检查屏幕录制权限

### 11.2 不应使用

- HDR 已保留
- HDR 无损截图
- 通用 HDR 保真
- HDR 认证
- 所有显示器效果一致
- P3 / HDR10 / JXR 已支持
- 已验证视觉效果（仅因文件成功生成时）

文案应简短、平静、使用 sentence case，并告诉用户发生了什么以及下一步可以做什么。

### 11.3 提示密度与承载方式

易用不等于把话说满。同一条信息只允许一个声道，并优先交给最省视觉成本的载体。

按以下顺序选择载体，只有前一级承载不了时才升级到下一级：

1. **结构与图标**：两个截图入口靠图标和快捷键区分身份，不再用副标题重述。
2. **控件当前值**：设置项显示真实取值（`Clipboard and folder`、`~/Pictures/Lumiere`、真实文件名示例），取值本身就是说明，不另写一句解释控件用途。
3. **状态行**：窗口底部常驻一行。静默时报告能力状态，指针悬停或键盘聚焦到某个操作时替换为该操作的提示。提示按需出现，不占用常驻版面。
4. **句子**：只在三种情况下出现——阻塞原因、用户看不见的后果、失败后的下一步。

补充约束：

- Banner 和状态行分工不同，允许共存。Banner 负责一句解释加一个动作，状态行只用两三个词标能力状态，
 不复述 Banner 那句话。
- 页脚是常驻 chrome，不因状态变化清空或只剩单边元素。
- 省略号是 macOS 的菜单语法，只出现在菜单项。窗口内的入口链接写 `Settings`，两个平台一致。
- 同一表面内不重复平台常识，也不解释标签已经说清的事。
- 设计意图和评审注释属于设计稿标注，不进产品界面。

## 12. 原型交付要求

### 12.1 页面与组件

- 主窗口：正常、检测中、权限缺失（macOS）、能力不支持（Windows）、Host 不可用
- 区域 Overlay：等待、拖拽、有效、无效、捕获中、取消、失败
- 托盘与菜单栏菜单
- 设置：输出、捕获、系统与关于
- 权限说明与系统设置引导（macOS）
- HDR 状态提醒

Windows 只画差异，不复刻整套画板。原因是重复画板会让同一个事实有两个出处，改一处要改两遍。
需要单独出图的差异只有五处：

1. 窗口控件位置与形态。macOS 交通灯在左，标题居中，标题栏不放图标；Windows 系统绘制的控件在
 右上，左侧放 16px 应用图标加标题，图标用 `app.ico` 原样方形，不额外倒角。
2. 权限模型。Windows 的 Graphics Capture 不需要用户授权，所以 macOS 那七个权限画板在 Windows
 上不存在；对位的失败态是「当前 Windows 版本不支持捕获」。
3. 快捷键写法与路径写法。
4. 托盘与菜单栏语义。macOS 写 `Open Lumiere`、`Settings…`、`Quit Lumiere`；Windows 写 `Open`、
 `Settings`、`Exit`。菜单栏是所有应用共用的表面，名字在消歧义，苹果自己也这么做；托盘菜单
 从本应用的图标点出，应用名是已给足的上下文。
5. HDR 提醒指向的系统设置位置。

其余表面（Overlay、Toast、设置行内容）两平台一致，不重复出图。

### 12.2 主题与平台

- 深色是 MVP 唯一交付主题，Windows 与 macOS 共用同一套深色视觉系统
- 不交付浅色主路径，也不跟随系统明暗切换
- 平台特有菜单、权限与窗口行为说明
- 键盘焦点态
- reduced motion 说明

不要求为两个平台复制完全独立的视觉系统，但必须标出平台原生差异。浅色主题推迟到 MVP 之后重新评估。

### 12.3 可点击流程

原型至少可完整演示：

1. 快捷键发起区域截图并复制成功。
2. 主窗口发起区域截图并保存成功。
3. 显示器截图并同时输出，其中一个输出失败。
4. 首次权限未授予，前往系统设置后恢复（macOS；Windows 对位流程是能力不支持的解释与更新引导）。
5. Native Host 不可用，截图入口被诚实禁用。
6. HDR 状态为 degraded 或 unvalidated，用户理解提醒并继续。
7. 区域截图中途取消，并可立即再次截图。

## 14. 产品决策

### 14.1 已确认行为

- “当前活动目标”采用捕获命令到达 Native Host 时指针所在显示器；当前主屏幕和系统主显示器只作为目标解析失败时的恢复 fallback，不作为常态目标规则。
- 点击而未拖拽或未形成有效选区时取消截图，不生成最小选区或任何产物。
- 有效选区在释放鼠标后立即捕获；MVP 不提供捕获前移动、二次缩放或选区手柄。
- 默认输出目标是“剪贴板和文件夹”。在某一平台适配器尚未声明两个目标都可用时，界面必须诚实禁用该组合或要求用户选择已支持的输出，不能静默降级。
- MVP 默认保存格式为 PNG。固定文件名规则为 `Lumiere-yyyy-MM-dd-HHmmss.png`，例如 `Lumiere-2026-08-25-162345.png`；同一秒发生重名时追加从 `-2` 开始的数字后缀，避免覆盖已有文件。
- Region 选区使用 Native Host 返回的短期目标 token，以及以该目标左上角为原点的目标内逻辑坐标。Shell 拥有 Overlay 几何，Native Host 拥有平台坐标和像素换算。
- 取消以原生请求是否已经发出为责任边界：发出前由 Shell 清理 Overlay，发出后由 Native Host 清理捕获任务和原生资源。MVP 不增加捕获发出后的独立 interrupt 操作。
- Region 与 Display 分别拥有独立的全局快捷键设置，两者默认均不配置，避免首次启动时抢占系统或其他应用快捷键。用户显式录入后才由 Electron main 进程注册；冲突或系统拒绝注册时保留原有有效配置并明确提示，只有注册成功的值才持久化。托盘或菜单栏展示当前已注册的快捷键，所有入口复用同一个捕获命令路由。
- HDR 状态提醒默认开启并可全局关闭。它只控制 `unvalidated` 和可继续捕获的 `unavailable` 非阻断提醒；`ready` 静默，阻断状态和失败反馈不可被该设置隐藏。

## 15. 设计稿与实现的对接

设计稿在 Ardot，文件 ID `717150792637623`。它是设计过程的所在地，不是真值来源。真值分三层，
各有唯一出处，实现只看这三层：

| 事实 | 出处 | 形态 |
|---|---|---|
| 行为、状态、文案、平台差异 | 本文档 | 手写，可 diff |
| 色值、圆角、字号、间距 | `apps/desktop/src/renderer/src/tokens.generated.css` | 从 Ardot 变量导出，可 diff |
| 版式与像素细节 | `knowledge/design/design-export/lumiere-mvp-boards.pdf` | 从 Ardot 画板导出的快照 |

token 文件是生成物，逐字来自 Ardot 变量导出，不手改。要改值先改 Ardot 变量再重新导出，
否则下次导出会把手改冲掉。这条规则不是形式主义：`textTertiary` 已经因为只改画板不回写变量
漂移过一次，导出结果和画板不一致。

重新生成用 Ardot MCP 的 `export_variables`，参数 `format: css`、`colorFormat: hex6`。
画板快照用 `export_nodes`，`format: pdf`、根节点 `3:28`，落到
`knowledge/design/design-export/lumiere-mvp-boards.pdf`。Ardot 会话截图仍落在 `.cache/`，不入库。

变量命名带 `Lumiere-Dark-` 前缀，是 Ardot 变量集名拼出来的。实现时不要为了好看去重命名生成文件，
需要短名就在自己的样式层里做一层别名映射，这样重新导出只覆盖生成文件，缺哪个 token 会立刻断在
别名层上，而不是静默漂移。

渲染层现有 `styles.css` 还是占位视觉（金褐强调色、Georgia 大标题），与本设计无关，会在
接入 token 的那次改动里整体替换。
